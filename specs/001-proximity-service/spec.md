# Feature Specification: 주변 사업장 검색 서비스 (Proximity Service)

**Feature Branch**: `001-proximity-service`
**Created**: 2026-01-30
**Status**: Draft
**Input**: 사용자 위치 기반 반경 내 사업장 검색, 사업장 CRUD, 상세 정보 조회

## Assumptions

- 사용자 1인당 하루 평균 검색 횟수: 5회
- 사업장 상세 조회는 검색 결과 중 약 20%에 대해 발생
- 사업장 정보 갱신(추가/수정/삭제)은 전체 사업장의 약 1%가 하루에 1회 변경
- 검색 결과 페이지당 최대 20개 사업장 반환 (pagination 적용)
- 지도 이동/줌 변경 시 viewport 내 사업장을 자동 재요청한다 (디바운스 500ms). 단일 요청당 최대 200건으로 제한하여 대량 요청을 방지한다.

## Scale Estimation

| 지표 | 산출 근거 | 값 |
| ---- | --------- | -- |
| DAU | 주어진 조건 | 1,000,000 |
| 등록 사업장 수 | 주어진 조건 | 1,000,000 |
| 일 검색 요청 | DAU × 5회 | 5,000,000 |
| 평균 검색 QPS | 5,000,000 / 86,400 | ~58 |
| 피크 검색 QPS | 평균 × 5 (피크 배율) | ~290 |
| 일 상세 조회 요청 | 검색당 결과 20건 × 20% 클릭 = 4건/검색 → 5M × 4 | 20,000,000 |
| 평균 상세 조회 QPS | 20,000,000 / 86,400 | ~231 |
| 피크 상세 조회 QPS | 평균 × 5 | ~1,157 |
| 일 쓰기 요청 | 1,000,000 × 1% × 1회 | 10,000 |
| 평균 쓰기 QPS | 10,000 / 86,400 | ~0.12 |
| 읽기:쓰기 비율 | (5M + 20M) : 10K | ~2,500 : 1 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 주변 사업장 검색 (Priority: P1)

고객이 현재 위치를 기반으로 원하는 반경 내의 사업장 목록을 검색한다. 위치는 Browser Geolocation API로 자동 획득하며, 반경은 0.5km, 1km, 2km, 5km, 20km 중 선택할 수 있다. 검색 결과는 지도 위 마커 + 반경 Circle + 사이드 리스트로 동시 표시된다.

**Why this priority**: 서비스의 핵심 가치. 이 기능 없이는 다른 모든 기능이 무의미하다.

**Independent Test**: 브라우저 접속 시 현재 위치가 지도에 표시되고, 반경 선택 후 검색 시 마커/Circle/리스트가 동시에 렌더링되는지 확인. 반경 변경 시 Circle 크기와 마커가 적절히 업데이트되는지 검증.

**Acceptance Scenarios**:

1. **Given** 고객이 브라우저로 접속하고 위치 권한을 허용하면, **When** 페이지가 로드되면, **Then** 지도가 현재 위치 중심으로 표시되고 파란 마커가 현재 위치에 표시된다.
2. **Given** 고객이 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 현재 위치 주변의 사업장이 자동으로 로드되어 마커+리스트가 표시된다. 반경 선택은 줌 프리셋으로 동작하여 해당 반경에 맞는 줌 레벨로 이동하고, viewport 내 사업장이 자동 로드된다.
3. **Given** 고객이 반경을 1km에서 5km로 변경하고, **When** 재검색 버튼을 누르면, **Then** Circle이 5km로 확장되고, 지도 줌 레벨이 자동 조정되며, 마커와 리스트가 업데이트된다.
4. **Given** 고객이 반경 0.5km로 검색하고, **When** 해당 범위에 사업장이 없으면, **Then** 빈 Circle만 표시되고 "주변에 등록된 사업장이 없습니다. 반경을 넓혀보세요." 안내 메시지가 표시된다 (EC-1).
5. **Given** 고객이 지도를 드래그하여 이동하면, **When** 500ms 후, **Then** 새 viewport 영역의 사업장이 자동으로 로드되어 마커+리스트가 갱신된다.

### User Story 2 - 사업장 상세 정보 조회 (Priority: P2)

고객이 검색 결과 리스트에서 특정 사업장을 선택하면 영업시간, 사진, 주소 등 상세 정보를 확인할 수 있다.

**Why this priority**: 검색 후 사업장을 선택하는 것은 자연스러운 사용자 흐름이며, 상세 정보 없이는 사업장 선택의 가치가 낮다.

**Independent Test**: 특정 사업장 ID로 상세 정보를 요청하여 영업시간, 사진, 주소 등이 정상적으로 반환되는지 확인.

**Acceptance Scenarios**:

1. **Given** 검색 결과에 사업장 마커와 리스트가 표시되고, **When** 고객이 지도 마커를 클릭하거나 사이드 리스트에서 사업장을 선택하면, **Then** 지도에 Popup으로 요약 정보가 표시되고, 사이드 패널에 이름, 주소, 영업시간, 사진 등 상세 정보가 표시된다.
2. **Given** 고객이 사업장 상세 정보를 보고 있고, **When** 해당 사업장에 사진이 등록되지 않았으면, **Then** 기본 이미지(`no-photo.svg`) 또는 "등록된 사진이 없습니다" 안내가 표시된다.

### User Story 3 - 사업장 정보 관리 (Priority: P3)

사업장 소유주가 자신의 사업장 정보(이름, 주소, 영업시간, 사진 등)를 추가, 수정, 삭제할 수 있다. 변경된 정보는 최대 24시간 이내에 검색 결과에 반영된다.

**Why this priority**: 사업장 데이터 관리는 서비스 운영에 필수적이지만, 검색과 조회가 먼저 동작해야 의미가 있다. 또한 Eventual Consistency 정책에 따라 즉시 반영이 필요하지 않다.

**Independent Test**: 사업장 소유주가 신규 사업장을 등록하고, 24시간 이내에 해당 위치 근처에서 검색 시 결과에 포함되는지 확인.

**Acceptance Scenarios**:

1. **Given** 사업장 소유주가 인증된 상태에서 관리 모드로 전환하고, **When** 지도를 클릭하면, **Then** 클릭 지점에 임시 마커가 표시되고 좌표(위도/경도)가 등록 폼에 자동 입력된다.
2. **Given** 소유주가 지도 클릭으로 좌표를 입력하고 사업장 이름, 주소, 영업시간을 폼에 입력한 후, **When** 등록 버튼을 누르면, **Then** 사업장이 생성되고 지도에 새 마커가 추가되며, 24시간 이내에 검색 결과에 반영된다.
3. **Given** 소유주가 관리 모드에서 기존 사업장 마커를 클릭하고, **When** 수정 폼에서 영업시간을 변경하고 저장하면, **Then** 변경 사항이 24시간 이내에 상세 조회에 반영된다.
4. **Given** 소유주가 관리 모드에서 기존 사업장 마커를 클릭하고, **When** 삭제 버튼을 누르면, **Then** 마커가 지도에서 제거되고 24시간 이내에 검색 결과에서 제외된다.
5. **Given** 소유주가 아닌 사용자가 사업장 수정 또는 삭제를 시도하면, **When** 요청을 보내면, **Then** `403 Forbidden` 오류가 반환된다.

### Edge Cases

#### EC-1: 검색 반경 내 사업장이 없는 경우

빈 리스트(`[]`)와 함께 `200 OK`를 반환한다. 프론트엔드에서는 "주변에 등록된 사업장이 없습니다. 반경을 넓혀보세요."라는 안내 메시지를 출력한다.

- **API 응답**: `{ "businesses": [], "total": 0, "page": 0, "size": 20 }`
- **HTTP Status**: `200 OK` (오류가 아닌 정상 응답)

#### EC-2: 유효하지 않은 좌표 (범위 초과, Null)

API 계층(Validation)에서 `400 Bad Request`를 반환한다. DB 트리거는 최후의 보루로 두고, 애플리케이션 레벨에서 먼저 차단한다.

- **검증 계층**: Controller → `@Valid` + Bean Validation (`@NotNull`, `@Min(-90)`, `@Max(90)` 등)
- **방어 계층**: DB `CHECK` 제약 조건 + Trigger (애플리케이션 우회 시 최종 방어)
- **응답 예시**: `{ "code": "INVALID_PARAMETER", "message": "위도는 -90에서 90 사이의 값이어야 합니다" }`

#### EC-3: 중복 사업장 등록 시도

동일 소유주(`owner_id`)가 동일한 이름과 좌표로 등록 시도를 할 경우 `409 Conflict`를 반환한다.

- **유니크 제약 조건**: `UNIQUE(owner_id, name, latitude, longitude)` — DB 레벨에서 중복 방지
- **응답 예시**: `{ "code": "DUPLICATE_BUSINESS", "message": "동일한 이름과 위치의 사업장이 이미 등록되어 있습니다" }`

#### EC-4: 피크 시간대 트래픽 초과

API Gateway 또는 로드밸런서 레벨에서 Rate Limiting(사용자당 분당 요청 제한)을 적용하여 시스템 전체 셧다운을 방지한다.

- **Rate Limit 정책**: 사용자(IP 기반)당 분당 60회 검색 요청 제한
- **초과 시 응답**: `429 Too Many Requests` + `Retry-After` 헤더
- **시스템 보호**: Rate Limit 이후에도 트래픽이 과도할 경우, Redis 캐시가 DB 부하를 흡수하여 서비스 가용성 유지

#### EC-5: 삭제 후 24시간 이내 검색 결과 노출

검색 결과(LBS) 리스트에는 Eventual Consistency 윈도우 동안 삭제된 사업장이 나타날 수 있다. 고객이 해당 사업장의 상세 정보를 클릭할 경우, 상세 조회 서비스(Business Service)에서 `404 Not Found`를 반환하여 데이터 무결성을 보장한다.

- **검색 결과**: 캐시 TTL(10분) 또는 Replication Lag로 인해 삭제된 사업장이 일시적으로 노출 가능
- **상세 조회**: Primary DB에서 존재 여부를 확인하여 삭제된 경우 `404 Not Found` 반환
- **응답 예시**: `{ "code": "BUSINESS_NOT_FOUND", "message": "존재하지 않거나 삭제된 사업장입니다" }`
- **프론트엔드 처리**: 상세 조회 404 수신 시 검색 결과 리스트에서 해당 항목을 자동 제거하고 안내 메시지 표시

#### EC-6: Geolocation API 실패 (권한 거부 / 타임아웃)

Browser Geolocation API가 실패하면 서울 시청 좌표(37.5665, 126.9780)를 fallback으로 사용하고, 안내 메시지를 표시한다.

- **실패 원인**: 사용자 권한 거부(`PERMISSION_DENIED`), 위치 확인 불가(`POSITION_UNAVAILABLE`), 타임아웃(`TIMEOUT`)
- **fallback 동작**: 지도를 서울 시청 좌표(37.5665, 126.9780) 중심으로 표시, 파란 마커 대신 회색 마커
- **안내 메시지**: "위치 정보를 가져올 수 없습니다. 기본 위치(서울 시청)를 표시합니다."
- **사용자 복구**: 지도 클릭으로 원하는 위치를 수동 선택 가능

#### EC-7: HTTPS 미사용 환경

Geolocation API는 HTTPS 환경에서만 동작한다. HTTP 환경(localhost 제외)에서는 위치 권한 요청을 스킵하고 기본 좌표를 사용한다.

- **감지 방법**: `window.isSecureContext` 확인 (`localhost`는 secure context로 취급)
- **fallback 동작**: EC-6과 동일 (서울 시청 좌표, 회색 마커)
- **안내 메시지**: "보안 연결(HTTPS)이 아닌 환경에서는 위치 서비스를 사용할 수 없습니다. 지도를 클릭하여 위치를 선택해주세요."

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 두 가지 검색 방식을 제공한다: (1) 위도, 경도, 반경을 입력받아 해당 범위 내 사업장 목록을 반환한다 (반경 검색). (2) Bounding Box 좌표(SW/NE)를 입력받아 해당 영역 내 사업장 목록을 반환한다 (viewport 검색). 프론트엔드는 viewport 검색을 기본으로 사용한다.
- **FR-002**: 반경 선택지는 0.5km, 1km, 2km, 5km, 20km 중 하나여야 한다.
- **FR-003**: 검색 결과에는 사업장 이름, 주소, 거리(사용자 위치 기준) 정보가 포함되어야 한다.
- **FR-004**: 검색은 Viewport 기반으로 동작한다. 지도 이동/줌 변경 시 500ms 디바운스 후 현재 보이는 영역(Bounding Box) 내 사업장을 자동으로 재요청한다. "검색" 버튼은 현재 위치 중심으로 재센터링하는 역할을 한다.
- **FR-005**: 고객은 검색 결과에서 사업장을 선택하여 상세 정보(이름, 주소, 영업시간, 사진)를 조회할 수 있어야 한다.
- **FR-006**: 인증된 사업장 소유주는 사업장 정보를 추가, 수정, 삭제할 수 있어야 한다.
- **FR-007**: 사업장 정보의 변경은 최대 24시간 이내에 검색 결과에 반영되어야 한다.
- **FR-008**: 사업장 등록 시 위도(-90~90), 경도(-180~180) 범위의 유효한 좌표를 필수로 입력해야 한다.
- **FR-009**: 사업장 소유주가 아닌 사용자의 사업장 정보 수정/삭제 요청은 거부되어야 한다.
- **FR-010**: 검색 결과는 사용자 위치로부터의 거리 순으로 정렬되어야 한다.

### Key Entities

- **Business (사업장)**: 서비스에 등록된 사업장. 이름, 주소, 위치 좌표(위도/경도), 영업시간, 사진, 소유주 정보를 포함한다.
- **Owner (소유주)**: 사업장을 등록하고 관리하는 인증된 사용자. 하나 이상의 사업장을 소유할 수 있다.
- **Customer (고객)**: 위치 기반으로 사업장을 검색하고 상세 정보를 조회하는 사용자. 별도 인증 없이 검색 가능하다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 고객이 검색 요청 후 사업장 목록을 확인하기까지 1초 이내에 결과가 표시된다 (p95 기준).
- **SC-002**: 시스템은 1,000명 이상의 동시 검색 사용자를 성능 저하 없이 처리할 수 있다.
- **SC-003**: 사업장 정보 변경 후 24시간 이내에 검색 결과에 99% 이상 반영된다.
- **SC-004**: 사업장 상세 정보 조회 시 0.5초 이내에 결과가 표시된다 (p95 기준).
- **SC-005**: 검색 결과의 거리 정확도는 실제 거리 대비 ±5% 이내이다.
- **SC-006**: 피크 트래픽(평균의 5배) 상황에서도 검색 결과 표시가 2초를 초과하지 않는다 (p99 기준).
